# Isolated subfolder exclusion lab — not a release

This lab is based on the diagnostic buildprep snapshot. Folder removal and restore controls remain disabled. Existing library rows are not removed or hidden by the new operations. The older whole-root inventory detachment/hiding entry points are guarded off: a provider sweep cannot prove exclusive ownership, and the old dual-store preference/Room procedure was not crash-safe. Nothing here deletes, alters, or releases ebook files or grants.

The UI-disabled exclusion backend verifies observed provider edges, checks that saved roots match the already-initialized Room root inventory, quiesces the scanner, and commits a root-specific directory exclusion against the captured inventory generation. A corresponding restore clears only that exclusion and invalidates pending batches. Scans carry their generation into each batch and check root-specific exclusions against actual observed directory IDs in the Room write transaction. A root's own directory ID excludes that scan root; subfolder IDs exclude observed routes passing through the ID. Other grants remain independent. This is only future-scan suppression, not removal of existing library books. Existing legacy global exclusions still have their older cross-root behavior and need migration/review. Provider IDs, aliases, multiparent walks, asynchronous provider changes and Room/preferences drift remain unresolved.

No Android build, Room compiler validation, instrumentation, real SAF provider, service concurrency, process-death, migration or performance test has been run. The new host test is a SQLite model plus source checks, not Kotlin execution or evidence of Android correctness. Before enabling UI, ownership, overlap, durable reconciliation, legacy rows and shared routes must be solved; partial results must be honestly presented. The experimental scanner-generation argument is optional for older direct DAO callers/tests; production walk supplies it. Avoid calling lower-level DAO mutation primitives directly. Never ship or enable this lab as-is.
