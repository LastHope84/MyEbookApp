# Service race experiment — disabled, not for installation

Independent source copy, not a release or APK. No app, provider, or ebook was touched. The diagnostic application IDs are `com.example.myebookapp.serviceraces20261122` and `com.example.myebookapp.foxlet.serviceraces20261122`.

## Implemented in this experimental copy

- Pending notification-permission scan actions are in-memory only and cleared on Pause/Stop, so an old saved activity result cannot silently generate fresh authority after process death. Activity recreation may require repeating the request.
- A 256-bit random, in-memory-only token is armed after a successfully persisted explicit Start/Resume; old, null, redelivered or post-process-death intents cannot bind. Owner and token are checked under the scanner monitor before worker/service mutations. A new explicit request revokes the prior session, increments worker generation, and cancels prior work; the suspending processing mutex still serializes quiescence. The monitor is not held across suspend calls.
- A service promotes promptly before intent handling. Start failures, lifecycle callbacks, worker completions, foreground notifications and timeout handling are fenced; duplicate delivery tracks the latest delivered ID separately. An instance that accepted `stopSelfResult` cannot later take ownership. Its newly delivered request is not restarted; an error asks for another explicit scan after shutdown.
- Pause revokes/cancels the worker but retains the queue. Stop revokes/cancels and writes an empty root queue, leaving Room metadata and source files alone. Metadata-only and queue scan call paths remain present; active behavior is behind the disabled gate. Failed preference commit still poisons this process. Restore checks for pending in-memory authority and never starts work. Folder add/removal and V3 replay remain disabled.

## Important: not proven safe or ready

`LIFECYCLE_EXPERIMENT_ENABLED` is false in both user action and service admission paths. This is intentional: no scan is activated in this diagnostic. Do not change it for use until independent review and real Android fault/lifecycle tests pass. A request delivered to a retiring service will need explicit retry; no automatic handoff is attempted. Android's timeout deadline, delayed service destruction/start delivery, launch/promotion errors and stopSelfResult semantics require device tests, including duplicate/stale start IDs and concurrent controls. Existing Room/provider/noncancellable operations already in flight can finish after Stop; no claim of instant I/O quiescence or rollback. Process-local poison cannot prove that a failed SharedPreferences commit was durable across process death. Reconciliation and user recovery after such failures need device fault testing. Do not install this build over any real app or use it on real data.

The host tests check source and Python scheduling models, not the Android runtime. Kotlin JUnit tests exercise the actual authority class, but have not been executed in this workspace because Java, Gradle and Android SDK are unavailable. CI is configured to run them; Android instrumentation sources were adjusted for the new call signatures but were not run and older tests that expect an active scanner require an explicitly enabled test-only build. Before activation verify Kotlin compilation, package isolation, all relevant instrumented tests in isolated app storage, failure injection, and independent review.
