# Reversible scan membership experiment (2026-11-22)

**Do not expose or ship yet.** The folder adapter still reports `canRemove = false` and `canRestore = false`. This document supersedes the older whole-root experiment's statement that no visibility work exists.

## Implemented in app code

- Room v11 adds an authoritative configured-root inventory (initialized once from legacy saved-root preferences), scanner-created and explicit independent-book markers, app-owned root/book memberships, sweep inventory generations, and reversible hidden-book rows. Migration starts empty: older, imported, manual, ambiguous, or otherwise unknown rows are never inferred scan-owned. Scanner inserts only mark a new row scan-owned after exact SAF route verification; a manual insertion (including a URI collision) marks the row independent and unhides it. Memberships are positive observations; old observations from active roots conservatively keep a book visible.
- Experimental whole-root detach quiesces the worker, checks saved roots against Room, rejects queued roots outside the inventory, sweeps every configured root, and records each route under that sweep generation. A null cursor, loading/error extras, empty document ID, missing MIME/name, inaccessible root, excluded route, dot directory, cycle, duplicate directory route or unresolved identity prevents a complete sweep. The DAO transaction checks generation, exact Room-configured roots, completed roots, exclusions, and unresolved identities; only scanner-owned, freshly observed target members with no independent marker or other inventoried root membership are hidden. The tombstone and hidden rows commit together before preference/journal edits. Existing rows/IDs, shelves, covers, reading metadata and conversions remain intact. No ebook file or grant is deleted, moved or released.
- Library, FTS search, shelf counts and lists, recent/recently added, bulk-ID selection and conversion visibility use the same hidden-row filter. A hidden converted output does not suppress its original. Metadata work and duplicate candidates omit hidden records. Raw identity/maintenance DAO methods intentionally retain access to underlying rows. Add-folder invalidates the inventory and reveals hidden entries *before* writing preferences; restore saves the preference, then atomically clears the tombstone and invalidates the inventory/reveals rows. Unhide-on-new-observation and explicit manual/converted-output association are transactionally recorded. These fail open for book visibility on incomplete evidence.
- The 10→11 migration recreates the route identity index at the correct columns, including if it was absent or had a wrong definition, without touching book data. Android migration fixtures were adjusted to reconstruct older schema; these are not authentic exported historical schemas.
- Translation sources remain present. The checked-in translation input and checked folder-preview overlay were refreshed; no push, release or APK has been produced.

## Important gaps / safety boundaries

1. The authoritative root inventory is initialized once from legacy saved-root preferences under the scanner gate; that one-time import cannot detect a previously missing or corrupt preference. Thereafter Room root configuration and expected roots are compared transactionally at detachment; a Room/preferences mismatch or queued root outside the saved set fails closed. This is still dual-store integration: the folder UI reads preferences and there is no automatic reconciliation after a partial write, or proof for cross-process access.
2. A SAF walk, even with every cursor reporting complete and with repeated/cyclic directory routes rejected, is not an atomic provider snapshot. A provider can change entries between listings, expose aliases or represent the same underlying ebook through different document IDs/authorities. Consequently the experiment cannot prove complete real-world ownership or freedom from provider races. The current sweep is not a substitute for device/provider concurrency tests.
3. Only newly scanner-created, positively verified rows can ever become scan-owned. Legacy rows intentionally remain visible, so this does not remove all books the user expects. Existing detached roots, any historical unresolved route, any scan exclusion, or unusual directory graph stops the entire detach. Re-adding a detached root must use the explicit restore method, not ordinary add-folder. Adding/restoring *any* root reveals all hidden rows; another complete sweep is required to hide candidates again. Whole-root backend only; subfolder removal is not implemented.
4. Room tombstone and SharedPreferences are separate stores. Failures after Room commit can leave stale saved roots or queued work. The tombstone blocks the exact route but there is no completed crash-reconciliation UX; older inherited exact-directory blocking across overlapping roots still needs review. The UI cannot safely present partial outcomes yet.
5. No Android SDK/Java/Gradle was available in this environment. No Android build, Room compiler/schema validation, instrumentation, actual SAF provider, scan cancellation race, process-death, grant or performance tests were run. Host Python tests execute actual SQL where applicable but cannot validate Kotlin, Room invalidation, provider behavior or lifecycle. Large-library cost of per-book provenance transactions and complete rescans is unknown. Keep this copy isolated until all of these are resolved.

Host check: `python3 -m unittest discover -s tests -p 'test_*.py'` (118 tests passing at preparation time; historical source-contract fixtures updated for v11 behavior). New Room instrumentation tests are written but unrun.
