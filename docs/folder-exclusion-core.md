# Experimental scan exclusion core — not library removal

`LibraryScanner.excludeFolderFromScans(context, configuredTreeUri, directoryId)` records an exact SAF authority/document-ID exclusion after two complete provider walks. It fails closed on inaccessible/incomplete/inconsistent trees, cycles, or a busy/paused worker. It returns `FolderRemovalResult`: `removedRows` is always zero; `retainedRows` is the full current row count; `candidateRows` is an advisory count only. An identical repeated walk is not an atomic provider snapshot: alias or membership may change before commit. No candidate is deletion authority and no ebook file is modified. Do not expose this as successful library removal.

The exclusion and the allowed-root set are stored in Room migration 6→7. A parent scan skips excluded directory identities and an excluded root is skipped. Roots independently configured inside a selected directory remain surviving routes. Every configured and queued root must be enumerable; an inaccessible root blocks the operation. Existing excluded paths are conservatively considered in previews.

The scanner has a non-blocking worker barrier: pause with a still-live paused worker fails immediately rather than waiting behind it. A caller must stop/wait for the worker to finish, then retry. New root scanning is blocked while exclusions exist unless that exact root was present when the first exclusion was recorded. `bookDao.observeScanExclusions()` reports the stored identities; `bookDao.clearScanExclusion(authority, documentId)` removes one. Clearing the last exclusion re-enables scanning new roots. Re-enabling does not automatically rescan. Existing SharedPreferences saved roots are deliberately unchanged and require UI presentation as excluded rather than removed; there is no UI integration in this change.

The allowed-root restriction prevents a newly added root inside an excluded subtree from silently bypassing the exclusion, but is intentionally restrictive: user-added unrelated folders also cannot scan until exclusions are cleared. There is no tested Android provider/Room migration/device execution. Host-side SQLite/source tests are not an Android build. The folder-selection UI must not call this feature 'remove folder' or claim that records were removed.
