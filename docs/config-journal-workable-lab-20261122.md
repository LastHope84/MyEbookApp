# Scan-intent journal lab (not a usable build)

This is an isolated, incomplete prototype. Add Folder remains disabled in both UI and scanner; remove/detach/restore remain disabled. No existing app installation is updated. App ID suffix is `.journallab20261122` (or `.foxlet.journallab20261122`).

The new Room `ADD_SCAN_V2` transaction stages a root and durable intent together and rejects excluded/detached roots. A separate replay primitive validates before/after sets, preserves an existing paused queue, commits folder and queue preferences, then clears the V2 journal in Room. It leaves interrupted work for an explicit resume. Legacy ADD journals are never treated as V2. The primitive is intentionally NOT called by the actual scanner or UI: a protocol on paper is not sufficient.

Critical blocker: every queue writer and service lifecycle callback must be gated from process startup through completion of replay. Otherwise an explicit stop performed after process restart but before replay can clear the queue and then replay resurrects it. Quiescing a worker must also wait for blocking provider I/O and cleanup, account for foreground-service start/completion callbacks and cancellation, and avoid losing wakeups. A durable, race-free definition of STOP vs incomplete ADD is needed. The new replay function's caller contract is not enforced yet. Do not enable it or expose its DAO completion method until that is solved. Persistable SAF permission acquisition/revocation and grant failure also need integration and testing. Explicit paused/running/stopped service state transitions and notification permission must be designed with the visible UI; if an add is committed but start fails, the user must have a visible resume path. No automatic process-start work.

Host tests include a SQLite transaction rollback test and a scheduling model showing the stop/replay counterexample; they do not execute Kotlin. Android instrumentation tests are added for real Room/preferences restart-boundary states and rollback, but are unrun here and do not emulate actual process death, a SAF provider, service callbacks or preference write errors. Android compile is unverified. A device/emulator suite must inject each write failure and kill at each commit boundary, including repeated recovery, stopped/paused/running modes, concurrent scan controls, service lifecycle/worker completion, permission revocation, duplicate grants and overlapping roots. Also review every database writer and ownership evidence before any removal feature is enabled.
