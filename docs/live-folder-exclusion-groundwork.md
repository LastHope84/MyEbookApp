# Live exclusion groundwork — NOT folder removal

This is unfinished experimental code. Do not enable a remove button or distribute it as the requested feature.

* New Room v8 `scan_root_exclusions` records a `(rootUri, documentId)` pair. Scanner batches carry the actual observed directory-ID chain and check the current exclusion set inside the same Room write transaction as sightings, inserts and origin records. A new exclusion can be committed while the scan worker is running or paused; it does not take the scanner processing mutex. Already queued and in-flight batches carrying that path are rejected if their transaction starts after exclusion commit. Dedup keys are updated only for permitted entries.
* No library cleanup is implemented. Books inserted before exclusion, old/imported and ambiguous records, shared books, user metadata and original files are all retained. `FolderRemovalResult.retainedRows` is the total library count, not a count of books in the selected folder. Excluding a root does not remove the saved root. Do not label this operation removal.
* The collector currently walks the entire selected grant to validate that a directory is reachable; provider errors fail closed. This can be slow on large trees. Validation and database commit cannot freeze the provider. There is no cleanup proof.
* Paths represent an observed route, not stable provider ownership. A directory is processed once per scan. If an exclusion changes after a directory was visited through a route, a second route can be missed until a later rescan. More complete graph/ownership and generation/reconciliation design, transactional cleanup, and tests for 25k entries and overlapping grants are still needed.
* Historical global exclusions from the earlier prototype remain global and still apply across roots; the new records are root-scoped. New roots are no longer refused wholesale. Legacy rows require explicit migration/restore policy if that prototype ever ships.
* Room migration/instrumented tests, actual scanner concurrency/restart tests and a real Android build have not been run. Static Python and in-memory SQLite checks do not prove race safety. Old prototype tests assert the old global-exclusion behavior and need revision after the final design is chosen.
