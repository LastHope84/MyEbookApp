# Reversible path visibility projector — isolated experiment, not a release

## Current outcome
Folder removal/restore UI remains disabled. This is **not a working folder-removal feature**: there is no trustworthy issuer for complete per-book ownership and route evidence, so the proof function deliberately always returns null and no existing book is hidden. Historical routes, `scan_owned_books`, a completed scan or the absence of an `independent_books` row do not prove exclusive ownership. There is no provider-file deletion or rewrite. The existing old root-hide primitive is unsafe and remains guarded from its transaction entry point.

## What is added
The path-exclusion commit and restoration transactions now rebuild an experimental reversible visibility projection from the complete persisted exclusion set. It clears the projection first, rejects incompatible legacy exclusions or detached roots, checks root identities, constructs component-wise root-qualified paths, and uses the existing path decision model. A SQL prefilter and insert additionally require a forward scan-owned marker and no known independent owner. They are **necessary filters, not proof**, and the insert primitive is not safe to call directly. Only the unimplemented private complete-evidence issuer could supply eligible evidence; it must never be replaced with an attestation based on the currently incomplete observations.

The commit/restore transactions still validate the expected Room configuration and generation, and invalidate pending scan batches before rebuilding. The projection is in `hidden_scan_books`, so metadata, book rows and shelf associations are not modified. Invalidation, independent import and subsequent matching scans currently unhide entries, a conservative fail-open rather than durable folder removal. A root path denotes the master folder; nested path components denote subtrees; the decision model considers all exclusions and alternate routes. This describes the intended eventual projection logic, not proven end-to-end behavior today.

## Blockers before enabling
Implement and audit a generation-bound proof issuer that establishes complete independent/manual provenance and all relevant paths including multiparent/shared documents and all roots without assuming provider snapshots; cover creation, reimport, conversions, stale records, all mutations and ambiguity; prove invalidation and recovery when providers or grants change. Address Room/preferences divergence and process-death reconciliation; rework unconditional invalidation/scan unhiding into a safe durable policy; decide root-marker semantics in the projection; validate excluded descendant restore and provider changes. Preserve disabled UI until Android Room compilation, migrations, real provider/device tests, scan concurrency and crash/recovery testing pass. The current model is conditional, not certification of any issuer.

Host tests execute the actual SQLite prefilter, projection insertion and unhide queries, plus transaction rollback and source contracts; they do not run Kotlin, Room or SAF. There is no Java, Kotlin, Gradle or Android toolchain in this environment.
